## Delivered behavior and source decision

The reviewed normal-continuation registry now has **139 exact LLVM opcode
identities**. Its ruleset identity advanced from `user64-effects-v1.0` to
`user64-effects-v1.1`. The new `MOV32mi` and `MOV64mi32` bindings match the
six-field memory/address/immediate payload and reviewed prefixes; the 64-bit
form requires REX.W. They use the selected base/index GPR byte cells, do not
read prior memory, may-define `memory:any`, never must-define that whole cell,
and claim no flag write. The 64-bit form records an encoded imm32 with signed
extension to a 64-bit semantic value. Existing register and register-source
MOV bindings retain their behavior. Unknown forms remain explicit gaps.

The [pinned source/decoder review](stage-a-source-review.md) records AMD Volumes
2–3 SHA-256 values and PDF pages, exact real-dump bytes, LLVM operands and the
source-form discrepancy. `AMD64-F-0503` remains a table-reconciled source
candidate whose imm32 metadata cannot be used as an executable validation
constraint for the memory alternative without additional review. Its reviewed
register-only sibling already records sign extension. The Rust effect binding
uses the source prose and pinned decoder shape directly; no AMD64 form or
profile ledger status/digest was silently changed.

The two hash-pinned Breakpad fixtures now decode their faulting instruction:

| Captured fixture | Entry/seed | Local observed result |
| --- | --- | --- |
| `linux_null_dereference.dmp` | RIP `0x401f26`, `MOV32mi` | 1 decoded node, 1 structural edge, 1 later obligation, 0 missing seeds |
| `write_av_non_canonical.dmp` | RIP `0x7ff738721331`, `MOV64mi32` | 3 decoded nodes, 4 structural edges, 1 later obligation, 0 missing seeds |

These are **crash-IP-as-root** runs. The may-write and fallthrough represent a
possible successful normal continuation under the fixed analysis abstraction.
The captured store fault might not retire; no actual memory commit, fault
priority, handler path or crash root cause is inferred. The next checkpoint is
Stage B's independently established earlier captured entry and a nontrivial
backward address-producer slice. The previously published 137-opcode and
zero-decoded reports remain historical evidence for their exact older sources.

The new `AriadneEffectsChecks.tla` finite projection fixture compares four-
and eight-byte writes with a larger abstract `memory:any` cell and rejects a
whole-cell kill or missing address-register input. It does **not** validate
LLVM encoding, prove the AMD manual interpretation, or certify a complete
instruction step. New Rust tests check exact address views, signed imm32,
prior-memory weak updates and the rejection of incompatible raw shapes and
unreviewed prefixes. The effect mutation suite catches omitted address inputs,
spurious old-memory reads, whole-memory kills and missing extension in addition
to its six existing controls. Compile/launcher/protocol errors did not count as
mutation rejection.

The pinned source PDFs and matching LLVM 20.1.2 development headers were
retrieved into `/tmp` and SHA-256 checked, without system installation.
Testing used Rust 1.96.0, Apalache 0.61.0 and TLC revision `1476e7f` on
Linux/WSL. The full AMD64 TLA+/Lean proof suite and the intentionally failing
`--require-milestone register-core` acceptance gate were not rerun as passing
Stage A evidence; their ledger status remains **0/49** verified register cases
and **0/156** verified `ram-data` cases.

Neither text/DOT rendering nor the minidump reader was changed. Their tests
and source-bound gates were still exercised with the new input summaries.
There is no new PE/ELF reader, Rust ISA executor or JSON/production CLI in this
stage.

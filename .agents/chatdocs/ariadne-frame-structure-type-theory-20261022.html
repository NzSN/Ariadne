Six questions the current implementation can answer

Ariadne starts from one immutable snapshot and one selected thread. Its frame-to-frame products connect captured activations through admitted control-flow edges. Its semantic questions add supported, local value reasoning to that source.

Read the signatures as explanatory specifications. Records describe returned fields, sums describe alternatives, and refinements describe checks. The names below summarize the current contracts; they are not a new programming language, literal JSON schemas, or proofs that the Rust implementation satisfies every refinement. Actual entry points return Result<…, Error>; malformed evidence is an error.

Question you can askUseful answerCurrent selector
1. What structure was recovered in these frames?Per-frame instruction maps, typed edges, active-call links and unresolved boundaries.--frame-structure N:M
2. Can the represented graph connect the two anchors?A represented connection result and, when completed, its forward/backward corridor.--frame-connections N:M
3. Where are the cyclic regions?Strongly connected components (SCCs), cyclic markers and the component graph.The same connection report.
4. Which bounded instruction routes can be listed?Typed structural paths with a strict count bound and explicit search limits.--list-frame-paths N:M --path-count-bound NP
5. Can this local branch satisfy a point constraint?A model witness, scoped refutation, unknown, or conflicting premises.--frame-question Q.json
kind: alternative
6. What contributes to this fault address, and which writers remain possible?Separate value facts, candidate-origin assessments and obligations.--frame-question Q.json
kind: fault_dependency

These are mode selectors, not complete shell commands. Live commands also need the dump, decoder reference and output options shown in the CLI usage. Questions 2 and 3 are fields of one product. Questions 5 and 6 share a source, but general value transport between frames is currently unavailable.

1 · “What structure was recovered in frames N through M?” 
FrameRange = { N : Nat, M : Nat | N ≥ M }

recoverStructure : Capture(S) × FrameRange × Limits
                 → StructureSource(S, N, M)

StructureSource(S, N, M) = {
  frame_maps  : List<FrameMap(S)>,
  call_links  : List<FrameLink(S)>,
  diagnostics : List<Diagnostic>,
  source_binding : CheckedBinding(S, N, M)
}

FrameMap(S) = {
  frame : FrameIndex, entry : VA, pc : VA,
  nodes : FiniteSet<InstructionSite(S)>,
  edges : FiniteSet<TypedEdge(S)>,
  gaps  : List<UnresolvedBoundary>
}

Answer: which instruction starts and local edges were recovered; which active-call relationships were admitted; where recovery is missing, unsupported, conditional or stopped. Link admission remains an explicit property of each link.

Scope: a structural source can be sealed from a recovery prefix before complete dataflow. The live unwind adapter currently supports a finite Windows AMD64 profile. Missing captured bytes and unsupported unwind cases remain visible. A successfully bound source can still be partial.

Field names here are descriptive projections. Concrete records: FrameStructureMap, FrameStructureLink, BoundFrameStructure.

2 · “Does the represented graph connect frame N to frame M?” 
connections : StructureSource(S, N, M) × Limits
            → ConnectionReport(S, N, M)

Connection = Found
           + AbsentInRepresentedGraph
           + UnknownWorkStopped
           + UnavailableAnchors

ConnectionReport = {
  connection : Connection,
  graph_status, corridor_status : GraphLayerStatus,
  forward, backward, corridor : FiniteSet<Node(S)>,
  frontiers : List<UnresolvedBoundary>,
  receipts : WorkReceipts,
  premises : Premises
  …
}

corridor_status = CompleteForRepresentedGraph
  ⇒ corridor = ReachableFrom(G, start)
               ∩ CanReach(G, endpoint)

Answer: whether a route exists in the admitted graph and which nodes can lie along connecting walks in that graph. The corridor can include cyclic detours; it is not limited to nodes appearing in the displayed loop-free examples.

Anchors: frame 0 is innermost. For N > M, the start is frame N’s verified active call into N−1. The endpoint is frame 0’s captured PC when M=0, or frame M’s active call toward M−1 when M>0. For N=M, a validated common anchor can give a zero-edge route.

Scope: Found establishes graph connectivity. AbsentInRepresentedGraph requires sufficient completed reachability work on the constructed graph; an unresolved continuation may still reconnect in the actual program. Missing or ambiguous anchors prevent a cross-frame answer.

The actual connection is a bare enum. Examples and receipts are separate fields; Found can be established by reachability even if no example was retained. Implementation · Meaning and limits.

3 · “Which regions can cycle, and how do those regions connect?” 
CycleView(G) = {
  scc_status : CompleteForRepresentedGraph
             + WorkStopped + Unavailable,
  components : List<{
    id : ComponentId,
    members : FiniteSet<NodeOf(G)>,
    cyclic : Bool
  }>,
  condensation : FiniteSet<ComponentEdge>,
  receipt : WorkReceipt
}

cyclic(C) ⇔ |C.members| > 1
             ∨ HasSelfLoop(G, theSingleMember(C))

Answer: mutually reachable regions in the represented graph, including regions outside the corridor, with a graph of transitions between components. The cyclic formula uses the self-loop term only for a singleton component.

Scope: this is a projection of ConnectionReport, with its own work status. SCCs summarize finite topology without unrolling every possible iteration. They provide no observed iteration count or proof that a loop terminated. Recursive activations remain distinct even when their instruction addresses match.

Concrete component and condensation records · Finite connection model.

4 · “Show some instruction routes connecting those anchors.” 
listPaths : BoundPathSource(S) × FrameRange
            × { NP : Nat | NP > 0 } × SearchLimits
          → PathListing(G, start, endpoint, NP)

PathListing(G, u, v, NP) = {
  paths : List<Path(G, u, v)>,
  available : Bool,
  coverage : Coverage,
  enumeration_exhausted, truncated : Bool,
  stop_reason : Reason,
  gaps : List<Gap>,
  counters : SearchCounters
  …
} refined by length(paths) < NP

Answer: a bounded list of instruction sequences, preserving frame identity, edge kinds, active-call transitions and opaque-summary markers.

Two interfaces: --list-frame-paths uses its separately bound path source and permits revisits within the declared visit/depth limits. --frame-connections --example-path-count-bound NP produces separately bounded, loop-free examples. The connection source can be a recovery prefix; it does not automatically satisfy every preparation requirement of the path-listing route.

Scope: NP=10 retains at most nine paths; NP=1 permits zero. NP must also satisfy the relevant API or policy cap. Exhaustion is meaningful only with the declared search restrictions and evidence gaps. A structural path may contain infeasible branches or opaque calls. Neither an empty partial list nor a writer missing from the samples justifies exclusion.

Path source and listing · Enumeration contract.

5 · “Can the selected branch satisfy this register constraint at this point?” 
Constraint64(S) = {
  point : Point(S), bank : { n : Nat | n < 16 },
  width : {64}, mask : U64, value : U64
} refined by mask ≠ 0 ∧ (value & ~mask) = 0

AlternativeQuery = {
  frame : FrameIndex, site : VA, destination : VA,
  edge_kind : EdgeKind,
  endpoint : Constraint64(S)
}

askAlternative : BoundQuestionSource(S) × AlternativeQuery
                 × List<Constraint64(S)> × Evidence(S) × Limits
               → Assessment(S)

Assessment(S) = {
  verdict : Unknown + RefutedUnderModel
            + PossibleUnderModel + PremiseConflict,
  witness : Option<ModelWitness(S)>,
  layers : QuestionLayers,
  obligations : List<Obligation>,
  premises : Premises
  …
}

Answer: whether a selected alternative has a coherent model witness satisfying the declared point constraints, is refuted in the supported coverage scope, or remains unknown. Example: “Can the taken edge at 0x400306 still yield RCX=0 before 0x400310 in frame 1?” The linked fixture defines those addresses.

Scope: endpoint and condition constraints must be in the selected activation for current value reasoning. Cross-frame constraints report cross-frame-value-relation-unavailable. Positive witnesses require supported exact transfers and a coherent loop-free prefix. Refutations require completed work, closed control coverage and acyclic represented value flow. Conditional sources currently emit no positive model witnesses.

Point constraints: a user-supplied register condition is a hypothesis. Captured registers constrain the captured point; they cannot simply be substituted for an earlier branch input. The current fault PC supplies a before-state boundary, with its successful normal after-state unavailable.

The real verdict enum carries no payload; witness, receipts and obligations are sibling fields. This is the public alternative question kind, not a general solver language. Types · Decision procedure · Fixture and controls.

6 · “What feeds the fault address, and can this store be excluded for this load?” 
FaultDependencyQuery = {
  frame : FrameIndex, site : VA, access : Nat,
  load : Option<VA>, focus_writer : Option<VA>
}

askFaultDependency : BoundQuestionSource(S) × FaultDependencyQuery
                     × Evidence(S) × Limits
                   → Assessment(S)

FaultView(Assessment) = {
  values : List<PointBoundValueFact>,
  origins : List<{
    load_site : Option<VA>, site : Option<VA>,
    kind : OriginKind, disposition : Disposition,
    reason : Reason, pairs : List<AccessPairAssessment>
  }>,
  candidate_count : Option<Nat>,
  candidate_universe_sha256 : Option<Digest>,
  value_receipt, origin_receipt : QuestionReceipt,
  obligations : List<Obligation>
}

Answer: observed fault-point inputs, supported backward value relations and potential reaching origins. Where the access/instance evidence suffices, a candidate store may be excluded for the selected load. Its alternatives and exclusion scope remain explicit.

Scope: numerical fault observations currently require frame 0 at the captured fault instruction. Origin collection needs a compatible completed local analysis, either reused or completed under its own budget. With no explicit load, the collector walks actual reaching definitions to contributing load boundaries; a load does not reveal earlier memory contents.

Candidate preservation: focus_writer focuses detail and does not remove competing writers. External interference and open control/effects remain unresolved when their evidence is absent. Incomplete collection leaves coverage or candidate count unavailable. The feasibility verdict is Unknown/not applicable for this question kind; inspect its separate value and origin layers.

FaultView is a descriptive projection; value/origin receipts live inside layers in the actual assessment. An excluded candidate is not identification of the actual last writer. Dependency collector · Usage and boundaries.

A site identifies an instruction location

Node(S)  = { frame : FrameIndex(S), site : VA(S) }
Point(S) = { frame : FrameIndex(S), site : VA(S),
             moment : Before + After }

{ frame = 1, site = 0x400306, moment = Before }
  = “just before this instruction in captured activation 1”

site is the instruction’s semantic virtual address in the captured process. frame distinguishes recursive activations using the same address. moment distinguishes before/after facts. The source supplies the snapshot and activation identities that these short records depend on.

Repeated loop visits share a site. The pair (frame, site) does not identify a particular dynamic visit, historical iteration, file offset or source-code line. In an alternative query, site selects the edge’s source instruction and destination selects its target.

Unknown is part of the answer type

QuestionReceipt = {
  status : Finished + WorkStopped + Unavailable,
  work : Nat, elapsed_ms : Nat, reason : Option<Reason>
}

UnknownAssessment ≈ {
  verdict = Unknown,
  layers : Product<QuestionReceipt>,
  known_facts : Facts,
  obligations : List<{ frame, site?, kind, requirement, band }>
}

The second record is a conceptual view: actual facts are distributed among the bound source, values, origins and other assessment fields. An unknown verdict describes the question’s evidence and procedure scope. It does not prove that the problem is mathematically uncomputable.

Result for an affected layerMeaningWhat could improve it?
Unknown + FinishedThe implemented procedure finished but could not construct a witness or justified refutation.More precise admitted semantics, a coherent witness, or a stronger coverage argument.
Unknown + WorkStoppedA work limit or deadline interrupted the affected procedure.More of the relevant budget, when evidence and supported semantics suffice.
Unknown + UnavailableA prerequisite or supported relation is missing.The required captured evidence, compatible completed source, or implementation support.

Unknown bit values are represented conservatively: ⊤64 denotes all 64-bit values, while known bits restrict that set. Unknown branch conditions retain represented alternatives in abstract search. Missing targets remain explicit frontiers, including frontiers outside the displayed corridor that might reconnect later.

A useful structural result can coexist with unknown feasibility or origins. Finite graph reachability and SCCs handle cycles without enumerating execution histories; the current value checker has stricter cycle limits. A stopped search never supplies the missing premise for a refutation or writer exclusion.

Known-bit abstraction · Independent layers and obligations · Verdict rules.

Current answer boundary. These products explain represented connections and possible dependencies under their evidence and premises. Recovering the exact executed route, a historical loop count, the actual last writer, or the root cause requires additional evidence and contracts. General argument/value transport across activations is not implemented by the current question profile.

01Start with two meanings of “structure”

Graph structure

The instructions, typed edges, captured activations, active-call links, cycles and unresolved frontiers recovered from one snapshot.

A structural path follows those admitted connections.

Structural type notation

Records describe the components of an object; tagged sums describe its alternatives. Dependent indices and refinements express which objects belong together and which checks they satisfy.

We use this language to describe the graph and its evidence.

The type notation is an explanatory reconstruction of the current contracts. Rust uses nominal structs/enums, private constructors and runtime validation. The linked TLA+ specifications retain authority for the modeled behavior.

NotationMeaningExample in this explanation
{ field : T, … }A record, or named product.{ frame : FrameIndex, site : VA }
A × BBoth components are present.A route together with its scoped validation evidence.
A + BA tagged choice of alternatives.Next + Taken + Fallthrough + Jump + Indirect + Summary + Call
{ x : T | P(x) }The values of T satisfying a refinement.A path record whose successive nodes are joined by admitted edges.
Σ x : A. B(x)A dependent pair: a chosen value and evidence indexed by that value.A node sequence and checks for the edges of that exact sequence.
Γ ⊢ t : TA typing/evidence judgment under an explicit context.A validated structural path under the source’s identity and premises.

Type-level + means a tagged sum here. Arithmetic addition, where needed, is written as an explicit operation. A correctly shaped record still needs its semantic and identity refinements checked.

A small structural-subtyping example
{ frame : Nat, site : VA, evidence : Evidence }
    <: { frame : Nat, site : VA }

In a calculus with record width subtyping, a richer record can supply this narrower field view. Graph membership, snapshot binding and edge connectivity are additional refinements. The actual Rust API uses explicit views and validated bound objects.

02Index the graph by its actual evidence

Let S identify the immutable snapshot, Q the selected thread/range question, R the immutable source revision, and ΓG the source’s admitted premises. These indices prevent facts from unrelated captures, activations or revisions from being joined.

RawNode = { frame : Nat, site : VA }

Activation(S) = {
  thread : ThreadId,
  frame  : FrameIndex,
  identity : ActivationIdentity,
  unwind_and_call_evidence : Evidence
}

Node(S) = { activation : Activation(S), site : VA }

Source(S, Q, R) = {
  nodes     : FiniteSet<Node(S)>,
  edges     : FiniteSet<{ src : Node(S), dst : Node(S), kind : EdgeKind }>,
  context_edges : FiniteSet<ContextEdge>,
  frontiers : List<UnresolvedBoundary>,
  premises  : ΓG,
  binding   : CheckedSourceBinding(S, Q, R)
}

Here G is the derived route graph: its traversal edges are separated from retained context edges and unresolved frontiers. The actual FramePathNode stores frame and site. Its surrounding bound source supplies snapshot, activation, proof and revision checks. The dependent indices above make those surrounding obligations visible.

Recursion makes the index essential. (activation₁, 0x400200) and (activation₀, 0x400200) are different nodes even though the virtual address is equal. A record view that retains only site loses information needed for frame composition.

NodeOf(G) = { n : Node(S) | n ∈ G.nodes }

EdgeOf(G, u, v) = {
  e : G.edges |
  e.src = u ∧ e.dst = v ∧ SourceAdmissionAccepts(e, ΓG)
}

For a cross-frame Call edge, admission checks the active-call relationship: the caller’s call bytes and continuation, the child activation and the required unwind/ABI premises. Other calls can remain local opaque summary context. A structural call link carries a control relationship; transporting register values across that call requires additional evidence.

Source validation has an error result for malformed identities or proofs. Missing evidence can produce a valid partial source with explicit frontiers. A digest binds an identity; it does not by itself establish a branch outcome or capture authenticity.

03A path is a record refined by edge connectivity

RawPath = {
  nodes : List<RawNode>,
  edges : List<RawEdge>
}

Path(G, u, v) = {
  p : RawPath |
  length(p.nodes) ≥ 1 ∧
  length(p.edges) + 1 = length(p.nodes) ∧
  AllNodesBelongTo(p, G) ∧
  StartsAt(p, u) ∧ EndsAt(p, v) ∧
  EverySuccessivePairHasItsRecordedEdge(p, G)
}

Equivalently, describe a witness as a dependent package:

Path(G,u,v) = Σ k : ℕ. Σ ns : Vec(NodeOf(G), k+1).
 StartsAt(ns,u) × EndsAt(ns,v) × ∏ i : Fin(k). EdgeOf(G, nsᵢ, nsᵢ₊₁)

The tags of the selected edges remain part of path identity. Two sequences using different parallel edge kinds are distinguishable. Nodes can repeat when a route crosses a cycle; the reported search policy bounds enumeration.

Read the two path-construction rules 
u : NodeOf(G)
──────────────────────────────────────── EMPTY
[]u : Path(G, u, u)

edge : EdgeOf(G, u, w)     rest : Path(G, w, v)
──────────────────────────────────────── CONS
edge :: rest : Path(G, u, v)

The zero-edge witness []u stores the single vertex [u] and zero edges. It still requires a valid endpoint. In Ariadne’s frame query, frame indices satisfy N ≥ M ≥ 0. Frame 0 is innermost. The older start is its verified active call; the end is frame 0’s captured PC, or an older end frame’s active call. An arbitrary saved return PC is a resume address and needs the active-call validation described by the anchor contract.

In a calculus with refinement subtyping, Path(G,u,v) can be viewed as RawPath by forgetting its evidence. Constructing the stronger type requires connectivity and identity checks. Ordinary record field compatibility supplies only the raw shape.

“Structural” describes what this witness establishes: every step belongs to the admitted graph, with the declared anchors and identities. It packages connectivity evidence; semantic feasibility has its own additional components.

A missing route in a complete search of the represented graph establishes a statement about that graph. An unresolved frontier can hide additional program behavior, so the result retains its recovery and search scope.

04Semantic refinements need their own witnesses

For a local path in one activation, let H contain the question’s explicit hypotheses and φ its endpoint predicate. A semantic witness adds an admitted initial assignment and a checked replay:

FeasibleWitness(Ga, Γa, H, p, φ) = Σ ρ : AdmittedInitialState(Γa, H).
  ReplayAllRequiredTransfers(Γa, p, ρ)
  × SelectedBranchConditionsHold(p, ρ)
  × EndpointSatisfies(ρ, p, φ)

Ga is the graph restricted to the selected activation. The current endpoint predicate φ is an admitted masked GPR constraint at an explicit before/after point. A nonempty abstract value set can guide the search; a positive model witness requires a coherent concrete assignment and the necessary supported semantics.

AlternativeAnswer =
    PossibleUnderModel { local_witness : FeasibleWitness(...) }
  + RefutedUnderModel  { scope : RefutationScope,
                         evidence : CheckedNoWitnessWithin(scope) }
  + Unknown            { obligations : List<MissingEvidenceOrWork> }
  + PremiseConflict    { conflicting_hypotheses_or_observations : Evidence }

This evidence-carrying sum is explanatory notation. The actual verdict is a bare enum; witnesses, obligations and scoped receipts are separate assessment fields. A refutation retains its declared coverage and model scope. Budget exhaustion or unsupported semantics can leave Unknown. Conflicting well-formed premises produce PremiseConflict and retain the conflicting evidence.

ObservedAs(p, record) = {
  event_mapping : CheckedMapping(record.events, p),
  identity_and_interval_binding : Evidence
}

A captured snapshot supplies bytes, stack data and point-specific observations. Those can support derived active-call relationships under the ABI premises. They supply no event-sequence witness for a complete historical instruction route. The current reports retain that execution-evidence limit explicitly.

06A frame result is a product of independently scoped layers

Layer(T) =
    Finished   { value : T, scope : Scope }
  + WorkStopped{ partial : Option<T>, reason : Reason }
  + Unavailable{ reason : Reason }

FrameResult = {
  frame_binding,
  structural_recovery,
  connections,
  resolution,
  feasibility,
  values,
  origins,
  execution_evidence
}

This is a conceptual packaging of payloads and progress. The product corresponds to the separate fields in QuestionLayers. Rust records the layer receipts there; the associated assessment holds witnesses, values and origin payloads. Each component retains its premises, point and work receipt. A useful graph can coexist with unresolved values. A stopped cycle-summary or example-search layer can coexist with useful local fault facts.

Why an empty sample list proves so little 
SampledPaths(G,u,v,NP) = {
  paths : List<Path(G,u,v)>,
  count_check : NP > 0 ∧ length(paths) < NP,
  search_scope : SearchPolicy,
  status : SearchStatus
}

Search policy retains deterministic edge order and the declared visit/work bounds. The list bound is strict: NP=10 allows at most nine retained paths. With NP=1, capacity is zero even when a path exists. Scope, frontier and stop information determine what a completed search establishes. A returned sample count alone establishes neither infeasibility nor global completeness.

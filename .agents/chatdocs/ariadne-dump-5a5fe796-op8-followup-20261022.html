What the implementation now supports

UWOP_SAVE_XMM128 (operation 8) consumes two unwind-code slots. The implementation validates XMM6–XMM15, calculates the save address using the frame base and scaled offset, and retains a complete 16-byte captured stack read. It checks code ordering, slot count, address arithmetic, alignment, frame-pointer ordering, stack bounds and read limits. Microsoft’s unwind format defines the operation and offset encoding.

The operation leaves RSP and GPRs unchanged. Ariadne’s public recovered context remains GPR-only: the saved XMM bytes are preserved as evidence, without claiming vector-register value propagation.

Fresh recovery uses captured-windows-amd64-unwind-v2. Both saved-report replay and live capture validation dispatch on the recorded profile. V1 continues to use its original operation-8 stop behavior; unknown profiles reject explicitly. The compatibility dispatch was reviewed in source, but no executable legacy replay campaign was run in this change.

Code: operation parsing, bounded stack reads and profile dispatch; owning-capture profile selection. The canonical contract records the scope and application result.

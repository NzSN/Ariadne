Structural frame report before dataflow: Stage 5.1

Context and follow-up

Status. Planning only, 2026-10-16. SF0–SF6 below are pending. No runtime, model, native or dump qualification is supplied by this document. Source review starts at 6192dee19a5b2f133177a21187952e28d603c2d9; the working tree also contains unrelated documentation cleanup that must be preserved.

Why this document exists. The canonical structural-report design addresses a concrete coupling: the retained caller run recovered control flow but exhausted dataflow before the existing frame binder could consume it. Stage 5.1 delivers a separate structural result.

What this document establishes. Implementation order, file ownership, interface decisions, finite policies, independent controls and remote acceptance for this stage. The investigation design owns the resulting API and contracts.

Where to go next. Read the canonical section, core implementation guide, formal-model guide, input interface and BAP usage. The existing frame-path plan and caller-coverage S6 ledger keep their separate gates.

What remains unresolved. Everything SF0–SF6 is unimplemented/unqualified. Preparation checkpoints, SCC summaries, path enumeration, new target/loop rules, backward values and writer refinement are outside this stage. A structural report does not discharge full caller completion or existing frame-path acceptance.

SF0: freeze interfaces and finite policies

Freeze private bound types and raw transport forms before implementing them. The source request/activation/proofs are immutable. The structure identity binds those inputs, its recovery prefix, producer/ruleset, limits and stop receipt in a separate hash domain from completed analysis. Avoid hash cycles. Freeze which selected frames and auxiliary caller-entry witnesses are retained. An independently validated auxiliary caller may establish an entry witness, but does not change the requested frame range; its evidence and work count against the same trusted policy.

Preserve the existing feature chain and register focused tests in the root manifest rather than adding another Cargo package:

Surface Intended feature/test boundary
Core RecoveryResult Standard library only, available in core-only builds; standalone recovery tests need no external features.
BAP proof-bound structural types/codecs Gate verification on bap; a reports-only build must not accept the BAP family by silently omitting proof fields.
File-backed factory and CLI input; add focused input/CLI test targets under tests/input/.
Report/replay controls BAP-enabled structural contract tests under tests/; retain current reports-only APIs and their gates.

The authoritative model must retain Ariadne.tla's recovery invariant: visited starts reflect attempts; decoded starts reflect admitted successful visits; pending and visited account for original roots and discovered local destinations; edges, provenance and obligations are exact. FinishRecovery leaves those control fields unchanged, so the structural product can seal a prefix before that action without claiming the original model's Done/ScopeClosed property. Model frame-link admission, partial-status propagation and budget stops as separate properties. Finite checks are not universal Rust/native refinement.

Policy layer Freeze and exercise
Open/read/unwind Artifact/read evidence, supported unwind profile, frame count and runtime-table entry bounds. The named Electron image exceeded the old 4,096-entry default.
Preparation Existing lifting/discovery/guard/target inputs and their distinct limits; successful final request is required for a trusted structure.
Owned source/proofs Nodes, edges, original captures, normalized request and proof bytes, checked references and arithmetic overflow.
Recovery producer Visit count, cooperative time and retained prefix/frontier size; stop before the next Visit.
Frame aggregation Total frames/nodes/edges and boundary/anchor evidence, with no inherited 8,192-node hard clamp.
Saved decoding/replay Host-selected byte/node/proof/replay limits checked before expensive allocation or work. A report cannot raise host caps using its own declared limits.
Rendering/publication Format/payload limits and bounded diagnostics if a valid self-contained report cannot fit. No silent graph clipping.

Choose finite defaults only after sizing the frozen workload. They are policy choices, not new arbitrary hard maxima. The existing frame-path 8,192-node, 4 MiB output and 8 MiB decode defaults are unchanged and do not govern this new family. Boundary and zero-limit semantics must be explicit.

Producer stops and verifier stops are different: a producer may emit a validated partial prefix with its pending work; a decoder that exhausts its verification budget must refuse a trusted bound result. Deadline receipts validate the exact recorded visit prefix and separately describe clock observations; replay does not pretend to reproduce elapsed time.

SF1–SF3: build the structural boundary

  1. Reuse Analyzer's deterministic Visit behavior. Publish only the core control projection and its work receipt; do not expose reaching/slice facts through the new type. Preserve the core-only dependency boundary.
  2. Validate the exact final prepared request through the current input ownership and proof-dispatch rules. Keep all effects needed for proof validation even though this producer does not propagate definitions. Never traverse a pending candidate continuation that is a final nondecodable Stop.
  3. Distinguish pending local work, failed decode endpoints, unknown indirect destinations, final unresolved guards, opaque call context and local edges leaving the declared function. Unfollowed call targets are not automatically pending local work; preserve call facts while following local summaries.
  4. Preserve the frame chain and independently available local maps if another frame cannot prepare or bind. A child without a runtime function entry may use only a separately verified parent direct-call entry witness; otherwise report the missing entry. Do not guess roots from saved PCs or slice seeds.
  5. Factor shared active-call evidence checks without widening their supported E8 profile or weakening the old completed binder. Equal VAs in recursive activations remain different frame nodes.

Today PreparationError::LimitReached contains a MaterializationReport, not publishable instructions/evidence/seals. Treat it as progress diagnostics only. Its unattempted_references may not yet be finalized; derive referenced-minus- attempted for progress when needed, and distinguish deliberately unqueued call references from actual local frontiers. Preparation checkpoint sealing is out of scope.

SF4: product and persistence

The proposed CLI is a separate mode:

ariadne-minidump <dump> --frame-structure N:M
    [--frame-structure-limits <policy.json>] [existing supported BAP/input options]

This is a planned interface, not an available command. Preserve existing frame index/thread/entry provenance rules. Define the structural policy bundle to cover the relevant unwind/read, preparation, recovery, validation and publication limits, so the real corpus does not silently inherit an unrelated default. Validate N >= M >= 0 against the recovered physical chain. An equal-frame selection yields one frame map, with no zero-edge-path claim. Missing frames in a truncated chain remain unavailable evidence, not an invented connection.

Reject combinations with --list-frame-paths, NP/path-count options and origin/assessment modes. Track explicit full-analysis backend options: an explicit --analysis-backend or native-core-only option is incompatible with v1 structural mode. The implicit existing default bap still governs old full-analysis routes; it must not falsely label the new projection as native-core execution. Report semantic_backend = bap and producer = rust-recovery/v1 separately.

V1 saved reports retain one self-contained, deduplicated evidence dictionary. Resolve and validate every reference. Decode untrusted raw forms first; only successful replay constructs a privately owned bound object. JSON, text and DOT expose the same structural facts and gaps. Reject unknown schema fields, duplicate keys, malformed addresses and contradictory counters. A missing anchor does not erase valid local maps; a frame-chain relation alone is never rendered as a proven CALL edge. The new type is not accepted by origin assessment or current path listing. Adding a native structural producer or a new path consumer is later work.

SF5: independent controls and remote qualification

Run all Cargo/native/model/replay/mutation/dump work in remote Windows WSL via the existing r_windev workflow. Hash-verify the task-owned source archive and frozen sibling dependency snapshot. Keep replay and mutation build directories separate under the remote root target/; preserve exact executable identities. Local work for this planning change is documentation/rendering/link validation.

Required independent cases:

  • Straight line, both arms of a diamond, cycle, recursion, unreachable seed, intentionally unfollowed call target, failed/out-of-function endpoint and incomplete indirect target.
  • Drained recovery with gaps; work-stopped prefix; zero recovery work; hard preparation failure; independently valid frame beside an unavailable frame.
  • Captured reached E8 link, uncaptured/unreached call, return/target mismatch, ambiguous call and repeated VAs in different activations.
  • Rehashed node/edge/gap edits, changed capture bytes/spans, wrong snapshot, request/activation/epoch/producer, missing proof and candidate-edge promotion.
  • Each trusted-host and producer limit at below/exact/above boundaries; integer overflow; proof dictionary corruption; oversized raw input and rendered output; verifier-budget exhaustion without trusted publication.
  • Projection equality with completed-control fixtures; zero dataflow/slice work; legacy proof/version replay and unchanged current path/origin behavior.

Add behavioral mutants for missing edges/frontiers, forged drained/coverage status, a Visit after queue drain, admitting an unknown guard's candidate edge, accepting an unreached call and ignoring an independent limit. Expected outcomes come from an independent oracle/model, not only the same producer and replay implementation. Existing native/capture regressions must name actual helpers and exercised ignored tests. The new producer makes no claim of native structural parity; optional native comparisons are separate evidence.

Run the applicable root checks remotely on the final source snapshot:

cargo fmt --all -- --check
cargo test --offline --locked
cargo test --offline --locked --no-default-features
cargo clippy --offline --locked --all-features --all-targets -- -D warnings
python3 tools/check_rust_layout.py
python3 tools/check_doc_links.py

SF0/SF5 must create and document the new structural model/oracle/mutation entry points before citing their commands as available. Ordinary Cargo success cannot substitute for ignored capture tests, model checking or a real dump.

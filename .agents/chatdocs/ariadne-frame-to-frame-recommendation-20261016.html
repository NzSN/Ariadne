What should frame-to-frame analysis aim to answer?

Keep frame-to-frame analysis, and make an evidence-bound partial control-flow map its primary result. Add a few bounded example paths and targeted value/dependency questions. Reserve claims about the executed history for evidence that actually identifies it.

The useful question is: “What connections between these verified frame anchors are represented, which remain unresolved, and what evidence would narrow them?” This gives a useful result even when full dataflow or path enumeration cannot finish.

1. “Not computable” combines different limits

QuestionLimitConsequence for Ariadne
Which path actually ran before this snapshot?Often not identifiable: different histories can leave the same captured state.More search cannot recover information the capture did not retain. Uniqueness needs additional evidence or a proof under adequate premises.
Can one node reach another in a finite recovered graph?Decidable. A graph traversal can compute reachability without enumerating every walk.Loops do not make structural reachability uncomputable.
Is an arbitrary unbounded program path semantically possible?Undecidable in the general unbounded program model.A universal exact solver is not a practical product contract.
Is a path possible within a finite state/step/semantic model?Decidable when the modeled state and transitions are finite and effective, but it may be expensive.Use explicit bounds and report the actual model, assumptions and resource stops.

A literally finite machine-state model has decidable reachability in principle. Its enormous state space and the missing past inputs still matter. General undecidability concerns an unbounded model; a timeout in our particular run does not prove undecidability. Cornell’s distinction between computability and tractability, and the unbounded computation model.

Two histories can produce the same observed state

Toy model, not a reconstruction of this dump. The input bit is not retained; the other modeled state is equal at capture.

Even an algorithm that lists both histories cannot choose which one happened from this observed state alone.

2. The current contract already makes an important relaxation

Ariadne’s implemented frame-path question lists bounded structural alternatives, not an executed trace. It preserves typed edges, activation identity, premises and gaps. Unknown data feasibility remains eligible. With NP = 10, it returns fewer than ten paths; an empty partial or unavailable list does not establish disconnection. Current contract; modeled completeness and unknown-result boundary.

I would keep that contract and its compatibility. Add the map below as a distinct report, so useful structural evidence can be presented before every expensive analysis layer completes.

3. Recommended primary output: frame connections, cycles and open frontiers

ShowMeaning
Validated frame identities and active callsBind the snapshot/thread/activation, saved slots, captured instruction bytes and supported unwind/call premises.
Known control-flow corridorShow represented routes from the selected start anchor toward the selected endpoint.
Unknown frontiers alongside that corridorMissing bytes, unresolved jumps, opaque calls, unsupported semantics and budgets remain visible.
Strongly connected components (SCCs)Collapse cyclic structural regions for navigation. Keep original nodes/edges available; iteration counts and loop semantics remain unresolved unless separately proved.
A few example routesA shortest known structural route and selected alternatives, when available. Examples do not establish the executed path, likelihood or full coverage.
Question-specific value and origin explanationsRefine a selected branch, input or candidate writer using its own accepted semantics and evidence.

For a closed represented graph, the corridor can be computed as:

known corridor = ForwardReachable(start) ∩ BackwardReachable(endpoint)

In a partial graph this describes the known connections only. An unresolved edge might leave that region and later reconnect. Keep such frontiers as possible continuations; absence from this displayed intersection is not a proof of irrelevance. A negative reachability claim needs adequate completeness or conservative unknown-edge semantics.

SCC condensation creates a finite structural ordering, but it supplies no data invariant or proof of an iteration count. Preserve that distinction when displaying a loop summary. Sound approximation is a useful analysis objective in its own right. Cousot and Cousot’s abstract-interpretation framework.

4. The first architectural change I would make

Introduce a separately validated structural-recovery artifact and partial frame-map report. It should bind original captured bytes, roots, activation, proof/graph identities and unresolved frontiers, with its own finite size/work budgets. A missing semantic continuation remains conditional or unknown; this mode cannot promote a candidate edge into an admitted one.

Keep the existing completed BoundInvestigation and full-query acceptance gates intact. The new artifact would provide the smaller contract needed for control-flow presentation. Current code already replays structural recovery without running reaching definitions when checking a guarded frame graph, so there is a concrete validation seam to extend. Existing structural replay.

Two current gates explain why reducing the path count has not helped this dump:

  1. BoundInvestigation requires Phase::Done. The frame binder consumes completed investigations. Caller dataflow exhaustion therefore yields missing-frame-query before path enumeration. Completed-analysis gate; binder interface.
  2. The binder and input validator separately enforce 8,192 total nodes. The retained caller alone has 9,589 decoded nodes, plus 778 callee nodes. This is another admission boundary, even after caller completion. It needs an explicit budget/admission design; changing the later path-count limit does not change it. binding budget; input budget.

The retained October 15 caller run reached one million dataflow actions and roughly 105.6 million reaching-definition links. The later refresh exercised caller structural recovery but did not complete that dataflow. This is a reason to separate structural reporting from full origin analysis, rather than interpreting the unavailable listing as an impossibility theorem. Exact retained results and qualification limits.

5. A practical order of work

  1. Structural report first. Specify the new artifact/report and its validation/model boundary, then show admitted frame anchors, available control structure and every relevant frontier. Keep full caller completion and parity as their own open milestones.
  2. Summarize cycles and offer examples. Compute reachability and SCCs, then spend a small separate budget on useful example routes. Once graph admission succeeds, NP = 2 permits at most one example under the current API; it cannot fix the earlier binding gates.
  3. Resolve the bottleneck for one investigator question. Use call-context inputs, endpoint constraints, fair target-resolver scheduling, or a checked loop invariant when they help that question. Keep refuted, possible and unknown alternatives distinct.
  4. Refine fault dependencies locally. Reuse the completed callee where applicable. The immediate chain cmp [rax+0x38] ← mov rax,[rsi+0x28] is useful even without a unique whole-function path. Assess selected candidate writers with alias and instance evidence. An omitted example route cannot exclude a writer; unknown memory, other threads and opaque effects remain alternatives within the relevant scope. Existing question and dependency; writer-preservation rule.

A result should report the status of each layer independently: frame binding, structural recovery, model-relative feasibility, value/origin refinement and execution evidence. Use unknown with a reason when a layer stops. “Proved in this bounded model” and “observed in a recording” need separate labels.

6. When the actual history is required

Use execution evidence covering the relevant original interval when it exists. Time Travel Debugging, for example, records a process execution for replay. A recording of a later reproduction describes that recorded run, not retroactively the execution behind the old dump. Trace ingestion would be a separate Ariadne capability, not an inference supplied by a full-memory snapshot. Microsoft TTD recording concepts.

My recommendation is to make the verified partial map and focused explanations successful product outcomes. Complete structural enumeration and semantic proofs remain useful optional achievements under their declared scopes.

§5.1: Publish structural evidence before full dataflow

The first deliverable should be a separately validated frame-structure report from successfully prepared inputs. It can show admitted local control flow, verified call anchors and unresolved frontiers while full caller reaching definitions remain unfinished.

This stage establishes a structural artifact and its trust boundary. SCC summaries, path enumeration, new loop resolvers, backward value constraints and writer refinement belong to later stages.

1. The boundary to introduce

BoundFrameStructure is a proposed name. It must be a different type and report family from BoundInvestigation and the current frame-path listing. Keep the existing Phase::Done requirement for dependency investigations and current path binding. Current completion check; current frame-path binder.

The minimal implementation can reuse the existing Rust recovery projection and identify that producer explicitly, while BAP remains the production semantic input. A native producer needs its own integration and qualification; the new mode must not imply that it ran or completed the native full analysis. An explicit structural CLI route should avoid the current native.complete()/completed-Rust-analysis path. Current CLI coupling.

2. Stop after structural visits, before FinishRecovery

validate the successful prepared request and its proof bundle
initialize the recovery machine from its unchanged entry points
while pending is nonempty and recovery work remains:
    perform the next deterministic Visit action
publish the validated recovery prefix and its stop reason

When the queue drains, the state remains phase = Recover with pending = {}. Do not take the extra step(): it executes FinishRecovery, constructs dataflow caches and enters Dataflow. The current frame verifier already stops before that action. Phase boundary; existing structural-only replay.

A drained queue is not semantic completeness. It means discovered local starts were attempted. Failed decodes, unknown targets and unresolved guards can remain. Keep separate fields for work completion and coverage gaps. Authoritative recovery boundary.

3. Use the final request and preserve its admission rules

The artifact must own or resolve immutable, replayable evidence for the exact normalized final request, roots, snapshot/artifact identity, thread/activation, captured bytes and source contributors, guard/target/composition proofs and their epoch/ruleset identities. A digest binds identity; it does not replace validation.

Replay the accepted final controls. A pending guard’s candidate normal continuation can exist solely for discovery; if the final guard is unknown, the final instruction is a nondecodable stop. §5.1 must show that boundary, not turn the candidate continuation into an admitted edge. No new roots come from slice seeds or guessed targets. Candidate/final validation.

The first version starts with a successful FilePreparedAnalysis. A hard preparation failure currently supplies only a progress report, without a publishable request and its complete evidence. Return preparation diagnostics for that frame and keep other validated frame maps; a certified preparation checkpoint is separate work. The new structural report therefore avoids full dataflow, but it still pays for bounded input preparation, lifting and proof validation. Current preparation-error contract.

4. What the first report should contain

PartRequired meaning
IdentitySnapshot, artifact, thread, physical activation, roots, normalized request and ruleset/proof identities. Semantic VAs remain distinct from graph identifiers.
Local graphVisited and successfully decoded starts, captured site evidence and original typed edges. Preserve edges into failed or pending endpoints using boundary records.
Recovery workdrained, budget_stopped, or not_started, with deterministic counters and a stop receipt.
FrontiersUnvisited local pending work; failed starts; incomplete indirect transfers; unresolved final guards; and relevant scope boundaries, each with its reason.
Call contextCall edges remain visible, while local discovery follows summary edges. Intentionally unfollowed callee entries are not automatically pending local work.
Frame relationshipsCross-frame CALL edges require captured direct-call bytes, matching return continuation, reached caller site and child-entry binding. Otherwise retain a frame-chain relationship annotation and explain the missing anchor.
Analysis scopeDataflow and slicing were not requested by this report. No origin result, feasible/executed path or writer exclusion is implied.

One failed frame or unverified link must not discard other valid local maps. Conversely, a forged identity, invalid proof or inconsistent graph is a validation error, not a routine partial result. Show preparation status, recovery status and frame-link status independently.

For example, recovery = drained and coverage = partial are compatible when an indirect target is unresolved. A frame-chain relation alone must never be drawn as a verified control-flow CALL edge. Existing active-call checks; frame composition rules.

5. Validation and budgets are part of the artifact

Define the artifact as an exact prefix/projection of the authoritative recovery machine. Recompute visited/decoded sets, edges, provenance, pending starts and obligations from the immutable request. A work stop preserves its frontier; it is not evidence of disconnection. Retain the original graph rather than filtering it into a corridor in this stage. RecoveryInvariant.

Give this new family explicit finite limits for input bytes, nodes/edges, captured/proof bytes, recovery visits, replay work, output and publication. Apply them consistently while producing, decoding and validating, before large allocations. Keep the current frame-path limits and schemas unchanged. The new report should not inherit the fixed 8,192-node binding clamp.

Size the policy against the actual workload. The retained pair has 9,589 caller decoded sites plus 778 callee sites. Its proof payloads alone are approximately 25 MiB for the caller and 7.4 MiB for the callee, before other evidence. Increasing the node limit while keeping a 4 MiB output allowance would not deliver a replayable pair. If a complete evidence payload cannot fit, return an explicit bounded diagnostic, not a proof-free artifact labeled valid. Workload and existing gate; retained sizing source.

These are regression expectations for that source-bound fixture, not configured discovery facts or universal counts.

Successful publication of a partial map is a valid §5.1 outcome; full caller S6 parity and the existing path-listing acceptance stay open.

Context and follow-up

Status. Focused §5.1 proposal, dated 2026-10-16. No runtime code, models, canonical designs or execution plans were changed; no build or fresh dump analysis ran.

Why this document exists. It narrows the frame-to-frame recommendation to its first structural-report delivery.

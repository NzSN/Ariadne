Stage 5.1 now provides validated recovery-only sources without full caller dataflow. The existing completed-analysis path binder still has its own completion and admission requirements.

A concrete order of implementation, source ownership, modeled properties, independent controls, finite budgets and capture acceptance for the read-only consumer of BoundFrameStructure. Stage 5.2 refers to the recommendation item; it is distinct from Stage 5.1's SF5.2 mutation-qualification task.

Where to go next. Read the owning design, structural source contract, implementation guide and formal-model guide. The old frame-path ledger and caller S6 ledger retain their separate gates.

What remains unresolved. All Stage 5.2 runtime/model/product/qualification work is pending. Finite host defaults, the exact source-fingerprint projection and codec embedding/replay receipts must be frozen in FC0. This stage adds no new unwinder, semantic target resolver, full dataflow, loop invariant, writer exclusion or executed-history inference. It does not close caller S6 or F4.

FC0: contract, identity and finite policy

Inventory the complete current Stage 5.1 source interface, report versions, conditional hypothesis behavior and old CLI routes. Retain baseline bytes for actual saved v1 and conditional v2 reports. The current source publication ID is codec-private: do not call a renderer from investigation to obtain it. Specify a source-facts fingerprint over the actual validated chain, selected range, roots, frame/query identities, recovery facts, active links, policies and hypotheses. Specify separate logical and publication hash domains with no cycles, and frozen canonical orderings.

Freeze one complete finite policy covering nested structural input/replay, eligible graph nodes/edges, adjacency construction, traversal work, SCC stacks, temporary/frontier/candidate bytes, BFS attempts, route length, deadlines, assessment replay and published bytes. Zero work limits stay real limits; malformed questions, scope and source evidence are rejected before work stops. Default sizing must carry the recorded 9,589+778 decoded frame pair and its source/proof payload; defaults are policy choices rather than hard maxima. This stage must not inherit old frame-path admission/output clamps.

Add the authoritative finite model before runtime acceptance. Its checked properties must include:

  • The represented graph and original typed frontiers are preserved.
  • Complete reachability sets equal finite closure under the admitted edges; exact corridor membership is the forward/reverse intersection.
  • Only completed work can produce graph-relative absence. Unknown continuations can hide reconnection; no status turns them into a program disconnection.
  • Complete SCC membership is a partition with mutual reachability and maximal components; its quotient is acyclic and preserves represented inter-component relations. Self-loop singletons are cyclic; recursive activations stay distinct.
  • A shortest witness has minimum edge count in the represented graph; further examples are valid loop-free typed routes with strict NP and bounded work.
  • Examples and truncation preserve all possible writers and inherited premises. Conditional hypotheses cannot be stripped or combined into a baseline claim.
  • Resource stops terminate fairly within the modeled schedule and remain distinct from invalid evidence and missing anchors.

The model abstracts concrete byte/hash validation and wall clocks. Its guide must state the adapter/source premises and exact Rust correspondence; finite checking is not a universal refinement proof. Register model/checker commands in Specs/README.md only when the files exist. Add an independent literal graph oracle whose expected closures and SCC equivalence come from a different finite procedure, not the SUT's outputs.

FC1–FC3: implementation and independent cases

Start at the new investigation interface. The source is immutable and privately validated. Keep route eligibility and boundary attachments explicit, including edges to undecoded/out-of-function destinations. Shared helpers may be factored only with legacy behavior/identity regression controls. Do not turn decoded callee references into local roots or follow arbitrary call-only edges.

Required graph cases:

Case Required observation
Straight line and diamond Exact corridor and shortest route; two branch alternatives retain their typed edge identities.
Parallel edge kinds Equal node sequences with different typed edges remain distinct examples.
Self-loop, two-node cycle, nested/connected SCCs Exact known partition/condensation and inspectable original members/edges; no iteration-count inference.
Cycle with an exit Finite traversal terminates; the exit stays visible and a shortest example needs no loop unrolling.
Disconnected represented graph Exact graph-relative absence only after complete work; scope and source gaps retained.
Unknown frontier outside the corridor Forward-reachable unresolved continuation stays visible even when its known destination cannot reach the endpoint. A completion adding reconnection cannot contradict a prior program-level negative claim because none was made.
Failed/pending/out-of-function endpoint Original edge and boundary identity retained; no invented terminal instruction or promoted route.
Missing/ambiguous active call or child entry Cross-frame corridor/examples unavailable; independently available frame maps/SCCs survive.
Recursion with repeated VAs Activation identities and exactly admitted younger-frame transitions retained; no cross-activation SCC merge.
Equal selected frame A validated identical anchor permits a zero-edge example only when NP allows it.
Work stops at every layer, NP=1 and zero budgets Source maps and completed independent layers survive; no false corridor, partition, shortest guarantee or absence.
Conditional source All dependent results retain original hypothesis identity; baseline verdicts and source proofs remain unchanged.

Implement iterative graph algorithms: no recursion proportional to graph depth. Examples use the admitted graph and do not require completed SCC work; their budgets and statuses remain independent. Stop provenance must identify the actual restricted operation. Do not retry indefinitely to fill an example count or reuse a partial SCC label as if the partition were complete. Minimize retained copies of large source/proof payloads and check allocation estimates/overflow before work.

FC4: product, replay and compatibility

The new JSON envelope embeds one unchanged structural source plus its binding and the derived assessment. Nested source decoding calls the existing strict decoder under a separately bounded host structural policy. Replay reconstructs the privately owned source before recomputing corridor/SCC/examples and comparing all claimed facts, statuses, IDs and work receipts. A verifier budget stop is a refusal to trust the artifact, not a valid unexplained graph.

JSON/text/DOT must show source selection and hypothesis premises, separate layer statuses, full memberships/typed frontier references, shortest guarantee scope, example restrictions, counters and stop reasons. A collapsed SCC must link to its member nodes/edges. Unclassified frontiers and non-corridor unknowns must remain navigable. Do not hide source evidence to make the envelope fit.

Factor live structural capture preparation into a private shared function where needed; preserve current --frame-structure output bytes and behavior. The proposed new flags are --frame-connections N:M, --example-path-count-bound NP and --frame-connections-limits FILE. Reject explicit full-analysis backend, old path-listing, entry/seed and explanation/assessment combinations. Keep bap as the old full-analysis default; it does not label the new graph consumer as native core execution. Library saved-source support does not require a new stdin replay CLI.

Run actual legacy v1/v2 structural replay, legacy path reports and current default full analysis as separate compatibility controls. Keep core-only, reports-only, BAP-only and input feature behavior explicit. All Rust sources belong under src/, fixtures/tests under tests/, with the root manifest/lock and root target/ layout.

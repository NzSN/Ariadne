How Stage 5.1 handles the hard cases

The plan would publish the structural facts it can validate and preserve the unanswered questions as explicit boundaries. It does not need to decide the executed history, every feasible path or whether a program loop eventually exits.

Its contract is: “Here are the recovered instructions, admitted edges, frame links and remaining gaps under this snapshot and these premises.” A partial report can be useful and valid without answering the harder semantic questions.

1. Why a loop does not make this recovery pass run forever

The input is a finite, frozen prepared request. Structural recovery records each attempted address in a visited set and queues only local destinations that have not been visited. Known back edges remain in the graph, but they do not cause repeated execution of the loop.

visited := visited ∪ {current}
pending := (pending ∪ local_successors(current)) − visited

Consequently, this core pass performs at most request.addresses.len() Visit actions, including failed attempts. A smaller work budget can stop it sooner. This bound concerns recovery over the prepared input; input preparation, proof verification and output have their own limits. Actual scheduling behavior; authoritative Visit rule.

These cases follow the plan’s delivery contract, finite-policy rules and input/recovery boundary. General undecidability concerns the unbounded program model; exhausting this finite analyzer’s practical budget is a different issue. Computability and tractability distinction.

3. “Validated” and “complete” describe different things

A report can be valid evidence of partial recovery. Validation establishes that its graph prefix, source binding and pending work were derived correctly. It does not establish that all control targets, earlier values or execution histories are known.

Illustrative planned result, not the finalized wire schema:

preparation:           ready
recovery:              drained
control gaps:          unresolved indirect jump at D
frame link:            unavailable; active-call evidence missing
dataflow / slicing:    not requested
executed history:      not inferred

Empty pending work means every discovered local destination was attempted. It does not mean every possible destination has been discovered. A missing or ambiguous active-call anchor leaves an unresolved frame link; stack adjacency can remain an annotation without becoming a verified CALL edge.

The separate structural type cannot be substituted for the current completed BoundInvestigation. The old Done gate remains in force for its existing consumers. Proposed independent statuses; existing completed-analysis gate.

4. What this means for the current cyclic/budget problem

Stage 5.1 directly addresses the caller’s expensive dataflow completion: its structural report would not need that phase. It does not replace the existing indirect-target resolver or solve its cyclic constraints.

For the remaining callee dispatches, there are two outcomes:

  • Preparation succeeds with unresolved targets: the structural report can contain the admitted graph and the unresolved dispatch boundaries.
  • Preparation itself hits a hard limit: v1 provides diagnostics for that frame, because the current error does not contain a sealed request and evidence graph. Recovering certified preparation checkpoints is separate future work.

This is a deliberate limit of the first version: it improves the useful output after successful preparation, but does not guarantee a graph for every capture. Preparation error payload; retained Case-4 failure mechanisms.

5. What the plan promises to validate

The planned acceptance tests distinguish a drained graph with gaps, a work-stopped prefix, hard preparation failure and invalid evidence. Mutations must fail when an implementation drops a frontier, promotes an unknown guard continuation, fabricates a frame call or labels unfinished work as complete. Decoder-budget exhaustion must not construct a trusted object.

The promise is bounded work under declared policies and honest evidence boundaries. It is not a promise to turn an unknown answer into yes or no. No path omitted by this report can justify excluding a memory writer. Planned controls and remote qualification.

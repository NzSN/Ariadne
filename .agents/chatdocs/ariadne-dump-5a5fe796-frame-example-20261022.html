Why the requested path is unavailable

1 · The first unwind rule is outside the current profile

The captured UNWIND_INFO at 0x00007ff77c9a8468 has header 01 41 14 00: version 1, no flags, 65-byte prologue, 20 code slots. Its first operation has bytes 41 68 25 00.

0x68 & 0x0f = 8      → UWOP_SAVE_XMM128
0x68 >> 4   = 6      → saved register XMM6
0x0025 × 16 = 0x250  → stack offset 592 bytes

Microsoft defines operation 8 as saving a nonvolatile XMM register, with its scaled offset in the next slot. Microsoft x64 unwind specification.

The baseline v1 unwind implementation accepted operations 0–5 with its additional checks. It returns unsupported-unwind-operation for operation 8. Consequently frame 0 has no recovered return slot or return PC, and frame 1 cannot be admitted. The captured table also contains further XMM saves.

2 · An opaque candidate keeps the alignment proof open

Local recovery reaches the prologue but cannot admit the normal continuation of movaps [rsp + 0x290], xmm10 at 0x00007ff77501e123. The guard result is unknown, with residual normal-or-alignment-fault-unresolved.

The following candidate at 0x00007ff77501e12c is MOVAPDmr, with captured bytes 66 44 0f 29 8c 24 80 02 00 00. Its encoding is outside the reviewed MOVAPS guard recognizer. It remains an opaque barrier with control.complete=false and transfer opaque-rsp-havoc/v1.

candidate collection: closure_complete = true
coverage barrier:     0x00007ff77501e12c
guard stop:           candidate-coverage-incomplete
RSP residues:         0xffff  (all 16 residues remain possible)
MOVAPS verdict:       unknown

The current coverage rule rejects closed-coverage claims when any barrier remains, then widens RSP residue facts throughout the candidate region. This leaves the earlier MOVAPS unresolved even with a Windows call-entry premise. The result expresses an analysis coverage limit; it establishes no runtime misalignment.

Both blockers matter. Supporting this unwind operation would remove the first barrier to recovering the caller. Reaching the captured endpoint also requires resolving the local guard/coverage limit. Completing one of these alone would not establish the requested route.

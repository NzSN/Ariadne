P2-C: exact prefix and size rules for instruction forms

P2-C turns broad manual statements and their exceptions into a checked, source-backed catalog of instruction forms: which prefix role and operand-size rule apply, under which conditions, and which exact source establishes them.

Current status: unfinished local work. Most of P2-C can proceed with the pinned manuals already available. The GF inverse-table question belongs to D/E and the full P2 exit; it does not prevent C's inventory work. LOCK and repeat source-scope disagreements are C's specific shared dependencies on E.

Why a general size rule is insufficient

In the ordinary variable-size general-purpose case, 64-bit mode commonly defaults to a 32-bit operand, 66h selects 16 bits and REX.W selects 64 bits with precedence over 66h. P2-C must establish which forms satisfy those premises and catalogue the exceptions.

Source exampleWhat C must distinguish
Non-byte ADD GPR/memory formsThe promoted/variable-size rules apply: usual default 32, 66h for 16, REX.W for 64, with form-specific conditions retained.
Byte-operand formsThey remain byte operations even where other opcodes in the same family are promoted to 64 bits.
CPUIDThe manual uses it as a fixed 32-bit example, unaffected by attempts to override its operand size.
Near branches and implicit-stack operationsDefault-64 groups require exact instruction/opcode and branch/stack qualifications. Their field widths are not interchangeable.
Single-byte INC/DEC encodings40h–4Fh become REX prefixes in 64-bit mode. The family still has other encodings; a reassigned byte does not make the entire operation unavailable.

Operand width, address width, immediate width, displacement width and implicit-counter width must be separate fields. A 64-bit branch target does not imply a 64-bit displacement. Repeat/count registers follow address-size qualifications. A mnemonic or a single “64-bit instruction” label cannot express these rules.

A mandatory prefix is a prefix value used to select an opcode/instruction form. For the SIMD and other encodings described by the manual, 66h/F2h/F3h can have that role instead of their familiar operand-size/repeat role. C must retain that distinction per form.

Concrete work packages

  1. C.1 — Establish the source map. Bind the five roots to exact source sections, table rows and note targets. Start with selected Vol3 Chapter 1, especially PDF pages 49–56; Appendix B, PDF pages 627–656; relevant Vol1 branch/stack/operand-size sections; and the individual instruction descriptions. Appendix B covers general-purpose instructions. SIMD mandatory-prefix exceptions need their own instruction sources.
  2. C.2 — Build the size/classification matrix. Review B.1 definitions, Table B-1 and its notes, B.3 invalid/reassigned forms, and B.4/Table B-5. For each form record fixed or variable size, default width, allowed size changes, required mode, special cases and source ownership. Reconcile summaries with instruction-specific rules. A “no REX required” list also contains fixed-size cases and cannot substitute for this matrix.
  3. C.3 — Build the prefix-role matrix. Classify each relevant 66h/F2h/F3h role as size override, repetition, opcode selection, ignored use or source-defined invalid/undefined use. Record requirements and exclusions, including relevant REX.W or extended-encoding prefix-selector interactions. Preserve unsupported applicability as unresolved work.
  4. C.4 — Enumerate LOCK/REP forms. A source-listed mnemonic is insufficient. LOCK on a memory-writing ADD form and LOCK on a register-destination ADD form have different applicability. For REP, identify count-only versus ZF-conditioned forms, count width and opcode-selector cases. Retain the LOCK-list and repeat-note disagreements for source adjudication. This task does not implement string loops or restart/fault semantics.
  5. C.5 — Produce typed records and independently review coverage. Each record needs an instruction-form selector, mode/applicability predicates, prefix/size rules, exceptions, dependencies, exact PDF/cell/row/note evidence and a current disposition. Keep every physical source occurrence while sharing semantic rule identities only where justified. Compare the inventory with the manual independently of the parser's own matches; unmatched material cannot disappear.
  6. C.6 — Validate and close the references. Reconstruct the pinned products, replay the source bindings and parameters, apply the A/B review engine, and run omission/ownership/target/role mutations. Resolve the five roots only after their required scopes have checked current dispositions.

What must be true before C is finished

  • Every required form in the selected C source scope is accounted for, including exceptions and invalid/reassigned cases.
  • Every applicable prefix/size rule has exact source and form ownership; notes and references target the correct table/section.
  • The five reference roots have complete checked dispositions, and unresolved source-scope questions remain explicit until resolved.
  • Fresh source replay reproduces the inventory, with no unmatched required material silently classified as harmless.
  • Negative controls reject omitted exception rows, swapped note-2 targets, byte forms incorrectly promoted to 64 bits, false mandatory-prefix roles, register-only forms admitted to LOCK and stale source identities.

Passing the existing selected-rule tests establishes the checks they exercise. It does not establish that the missing C inventory has become complete. Completing C would still leave D/E, F/G and final H obligations.

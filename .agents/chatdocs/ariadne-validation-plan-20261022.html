Three methods, with a clear job for each

U

Ordinary tests

Rust #[test] and Python unittest cover reviewed examples, errors and regressions. Integration tests launch the CLI and native helpers.

Does this concrete case obey its contract?
P

PBT · property-based testing

Generate input combinations and boundary cases. Compare against independent reference calculations, then shrink failures into reproducible regressions.

Does the property hold across generated cases?
M

MBT · model-based testing

Replay model-generated actions against the real analyzer. Compare observable states and transitions, including partial results and termination.

Does the implementation follow the model?

Native execution uses these same test methods. An ordinary integration test can invoke BAP or consume a real minidump. Its required helper, runtime and capture are declared test inputs.

Existing starting points: test matrix, core properties and core MBT. The coverage additions below are proposed work.

First restore the execution prerequisites: cached Cargo packages, the required MirrorRust dependency view and freshly built pinned native helpers/runtime. The current workspace review found these missing.

01Map contracts to tests

Inventory existing tests and campaign-script assertions. Assign each behavior a test owner, independent expectation, required inputs and exact execution command.

Exit: every required contract has an executable test or an explicit coverage gap.

02Complete ordinary test coverage

Reuse concrete input, core, investigation, report and protocol tests. Move deterministic assertions out of campaign scripts. Add parameterized compatibility and rejection cases where missing.

Exit: reviewed positive, negative and boundary cases execute through Cargo or Python unittest.

03Extend generated properties

Build on core, frame-path and unwind PBT. Add capture mapping, arithmetic admission, context validity, report tampering and resource-bound generators where the inventory finds gaps.

Exit: declared seeds, bounds and counts execute; failures shrink and become small regression cases. Preserve the existing 3,200-case routine baseline.

04Extend live model replay

Reuse core and Stage E replay. Exercise applicable core traces against Rust and native analyzers. Add missing runtime adapters for target/guard composition and frame-question scheduling.

Exit: every selected trace state matches the declared observation mapping; deliberate-bug controls demonstrate that observers detect intended deviations.

05Exercise native and captured inputs

Select ordinary integration tests that run the actual helpers and CLI. Independently inspect captured bytes/context before asserting answers. Add explicit release workload tests using the existing timing policy.

Exit: named synthetic and controlled-capture cases execute on the equipped host; missing selected prerequisites fail clearly.

06Make execution routine

Keep scripts responsible for invocation, fixture generation and isolated builds. Remove duplicated assertions after their replacement tests pass. Publish the exact commands in the maintained test matrix.

Exit: ordinary test results identify what ran, failed or remained unselected. Generated diagnostics live under ignored build/work directories.

Concrete assertions and performance expectations

Ordinary tests establish exact unsigned-base plus signed-displacement arithmetic, agreement with admitted address evidence, and unknown results for insufficient evidence. PBT explores boundary values and context combinations. MBT connects finite decision/transition expectations to the implementation where an adapter is required.

Run existing mutation transformations against the same observers; compilation failures or missing helpers do not demonstrate bug detection. Require the positive control to pass and the changed implementation to fail the intended behavioral assertion.

Explicit release tests retain the existing I5c 10 ms binding/assessment/rendering phase and 1,500 ms CLI ceilings, using one warm-up and five measurements. Preserve the separate I4 criteria and existing capture modes.

Explicit native and workload test groups

Freeze the exact named test inventory during stage 1, then select those ordinary Cargo/Python tests on the host with pinned helpers/runtime. Existing native Cargo targets include bap_core_analysis, bap_core_stateflow, input_bap_core and input_address_wrap_cli.

Run the applicable ignored tests explicitly. Workload timing tests run in release mode with isolated execution. Validate externally supplied captures when selected; portable fixtures cannot substitute for a required capture.

Keep replay and mutation build directories separate under target/. Perform heavy native/model execution on the equipped host according to the module guides.

Completion is visible in executed tests

  • Every required contract maps to a named test or property.
  • Every selected case executes; empty or partial selections cannot pass.
  • Expected results come from reviewed examples or independent oracles.
  • Missing selected tools or captures produce a clear failure.
  • Failures retain reproducible seeds or small regression inputs.
  • Current results identify their scope and required input/tool versions.

Validation establishes finite contract conformance under declared captured-evidence and trusted-BAP premises. Universal refinement, complete ISA coverage and historical execution/root-cause claims retain their separate boundaries.

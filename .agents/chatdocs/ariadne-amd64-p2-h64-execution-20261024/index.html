Source interpretations that remain unresolved

Near-branch 66h behavior within native-64 execution

The selected AMD Vol1 revision 3.25 has conflicting statements on adjacent pages. Table 3-9 on PDF 128 (printed 90) gives default 64 and possible override 16 for its seven near-branch groups. PDF 129 (printed 91) then describes their listed actions and operand size as forced or fixed at 64. Earlier default-size text and Vol3's Table B-5 discussion also permit a 16-bit override.

Actual extracted cells, both rendered pages and the current publisher PDF confirm this wording and the shared table cell. Targeted AMD-site searches found no correcting interpretation; they were not an exhaustive errata review.

Needed: an authoritative reconciliation of the 66h rule for these groups, or an explicitly selected conditional source-precedence hypothesis. Existing records retain summary-66h-rule;requires-form-qualification. This review finding is not a new machine-adjudicated boundary and does not change the original-boundary denominator.

GF inverse lookup

The selected Vol4 lookup maps both F0 and F1 to 5B. In its documented polynomial-011B field, F1 multiplied by the listed 5B gives 5A; independent inversion gives 23. The table retains 5B. An AMD correction or authoritative interpretation remains necessary for the full D/E/H exit. H64 keeps this instruction family in scope.
